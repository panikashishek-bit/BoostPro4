# Учебные данные

Дорисовывает месяц правдоподобной истории, чтобы пульт можно было увидеть
на настоящем объёме, не дожидаясь, пока он накопится сам. И стирает её целиком
одним запуском — перед тем, как показывать пульт живым людям.

```bash
npm run demo:seed          # дорисовать
npm run demo:wipe          # стереть всё учебное из всех источников
npm run demo:seed -- --dry # посмотреть, что получится, ничего не записав
```

## Правило, ради которого всё это написано

**Настоящие данные владельца не трогаются вообще.** Не меняются, не удаляются,
не переставляются, метку не получают. В лог и в базу приложения команда только
`INSERT`, в Google-таблицу — только `append` в конец.

**Учебная строка помечена всегда.** Стирание идёт строго по метке — ни одного
условия по датам, по номерам чатов или по «похоже на учебное»:

| Источник | Метка |
| --- | --- |
| `data/events.db` | `is_demo = '1'` |
| Google-таблица «Клиенты» | колонка «Демо» = «да» |
| Postgres, таблица `Booking` | `isDemo = true` |

**Граница священна.** Учебная история кончается вчера; сегодня и дальше — только
настоящее. Проверяет это `verify()` в `plan.ts`, и падает она до того, как будет
записана хоть одна строка. Дата визита у учебных записей тоже всегда в прошлом:
иначе учебная запись заняла бы живое окошко в календаре мастера.

## Файлы

| Файл | Зачем |
| --- | --- |
| `settings.ts` | метки, период, объём, чтение доступов |
| `random.ts` | случайность с фиксированным зерном |
| `plan.ts` | вся история как чистый расчёт + `verify()` |
| `sheet.ts` | Google Sheets на запись, без `googleapis` |
| `seed.ts` | команда «дорисовать» |
| `wipe.ts` | команда «стереть» |

## Откуда берётся форма

Из данных владельца, а не из головы: услуги и мастера читаются из базы, статусы
(`J1`/`J2`/`J3`, «ушёл»/«записался») и причины срыва — те же, что встречаются
в его настоящих строках. Выдуманы здесь только имена клиентов («Клиент 42»),
номера чатов из заведомо свободного диапазона `7000000xx` и телефоны вида
`+7 900 000-XX-XX`. Всё это нарочно опознаётся как вымышленное.

Обращения связные: `session_start` → несколько `message_in` → и **либо**
`session_success`, **либо** ничего. Между соседними обращениями одного дня —
больше 30 минут, иначе бот считал бы их одним разговором (`SESSION_TIMEOUT_MIN`).

Доходит до записи около 74%, а не все. Ровные 100% в счётчике «Довели до записи»
не бывают ни у кого, и учиться на такой картинке нечему.

## Настройки

Своего `.env` у папки нет и не будет. Команды запускаются с уже настроенными
файлами приложения и бота:

```
tsx --env-file=.env --env-file=bot_administrator/.env demo/seed.ts
```

Заведи им отдельные настройки — и первое же расхождение (другой `SHEET_ID`,
другой путь к базе) молча раскидало бы учебные строки мимо настоящих.

Ключ Google берётся **бота**: пульт просит права только на чтение, а тут надо
и дописать строки, и потом их удалить.

Что и сколько рисовать — константы в начале `settings.ts`: период, объём по дням,
доля дошедших, число клиентов, зерно случайности.

## Повторный запуск

`demo:seed` откажется работать, если учебные данные уже есть: второй запуск
удвоил бы историю. Сначала `demo:wipe`, потом `demo:seed`.

Спрашивает он **все три источника**, включая таблицу. Стирание таблицы —
единственный шаг, который ходит по сети, и единственный, который может
оборваться на середине; проверяй `demo:seed` только лог и базу, такой обрыв
выглядел бы как «всё стёрто», и вторая сотня строк легла бы в таблицу поверх
первой. Поэтому же `demo:wipe` начинает с таблицы: упадёт сеть — не удалено
ещё ничего.

Зерно фиксированное, поэтому «стёр и дорисовал заново» даёт ту же историю.
Любое расхождение на пульте после этого означает ошибку в коде, а не другой
бросок кубика.

`demo:wipe` оставляет в таблице пустую колонку «Демо» — она не мешает и нужна
следующему запуску. Бот про неё не знает: он пишет поля по своему словарю
и незнакомые колонки не трогает.
