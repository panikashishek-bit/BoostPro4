# Для кого и зачем

«ПроСервис» — онлайн-запись на услуги для небольшой точки с несколькими исполнителями: салон, барбершоп, автосервис, репетиторский центр, клиника. Движок обобщённый — «услуга + исполнитель + слот + запись»; домен задаётся seed-данными.

## Два пользователя

**Клиент** — записывается на услугу. Приходит с телефона, чаще вечером, когда салон уже не отвечает.

**Администратор точки** (или сам владелец) — держит расписание и записи. Ему же принадлежит решение поставить продукт.

## Задачи, которые продукт решает

Продукт закрывает две задачи целиком — по одной на каждого пользователя (их Core Jobs):

**Клиент: «Я хочу занять конкретное время у конкретного мастера — сейчас и без разговора».**
Большая задача над ней (Big Job) — получить услугу к нужному дню: подстричься перед поездкой, успеть на маникюр до пятницы.
Что для него «получилось» (success criteria): видно только реально свободное время; запись занимает минуту; не нужно звонить и ждать ответа; время закреплено, а не «мы вам перезвоним».
Чем решает сейчас: звонок, переписка в мессенджере, форма «оставьте заявку», приход без записи.

**Администратор: «Я хочу держать расписание и записи в одном месте, где они не конфликтуют».**
Большая задача над ней — загрузить исполнителей работой и не терять клиентов.
Что для него «получилось»: двойных записей нет; кто, к кому и когда — видно списком; услуги, мастера и график правятся без разработчика; отменить запись — одно действие.
Чем решает сейчас: тетрадь, таблица, заметки в телефоне, календарь.

## В чём ценность

Обе задачи выполняются с меньшими затратами сил, чем прежним способом.

Клиенту продукт **убирает целый слой мелких дел**: дозвониться, объяснить, что нужно, согласовать время, дождаться подтверждения. Остаётся четыре нажатия. Момент, когда это ощущается (Aha moment), — увидев сетку свободного времени, он понимает, что согласовывать уже не с кем.

Администратору продукт **снимает удержание расписания в голове**: занятость считается из графика и существующих записей автоматически, а пересечение проверяется ещё раз в момент сохранения — двойная запись не пройдёт даже при одновременных заявках.

## Чего продукт НЕ делает

Границы такие же важные, как функции — они удерживают проект в размере учебного:

- **Не принимает оплату** — цена только показывается, эквайринга и предоплаты нет.
- **Не напоминает о записи** — ни SMS, ни email, ни бот. Не пишет клиенту вообще.
- **Не даёт клиенту личный кабинет** — ни истории, ни переноса, ни самостоятельной отмены. Отменяет только администратор.
- **Не ведёт учёт отпусков, выходных и перерывов** — график недельный, повторяющийся.
- **Не различает роли и филиалы** — один общий пароль на админку, одна точка.
- **Не считает аналитику и выручку** — отчётов и дашбордов нет.
- **Не работает с часовыми поясами** — всё время локальное для сервера.
- **Не хранит фото, портфолио и отзывы.**

Всё перечисленное — не «недоделано», а сознательно вынесено за рамки: на воркшопах поверх этого ядра наращиваются внешний API, MCP и AI-агенты, и ядро должно оставаться читаемым целиком.
