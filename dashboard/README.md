# Пульт

Личный командный центр. Весь код пульта — в этой папке: чтение настроек,
проверка связи, счётчики и вёрстка страницы.

В коде приложения от пульта есть ровно один файл — `src/app/dashboard/page.tsx`,
и в нём три строки, которые зовут `dashboard/page.tsx`. Больше приложение о пульте
ничего не знает.

## Как открыть

Локально, включая соседние устройства в той же сети:

```bash
npx next dev -H 0.0.0.0 -p 3000
```

- со своей машины — http://localhost:3000/dashboard
- с телефона или ноутбука рядом — http://<ip-компьютера>:3000/dashboard

`-H 0.0.0.0` обязателен: без него Next слушает только localhost, и по локальному
IP страница не откроется.

На сервере пульт живёт по адресу `/dashboard` того же приложения. Отдельного порта
у него нет — снаружи видно только приложение, и пульт въезжает туда же.

## Настройки

Пульт читает ТОЛЬКО `dashboard/.env` — файл рядом с этим README. В `.env`
приложения, бота и менеджера он не заглядывает. Поэтому папку можно скопировать
в другой проект целиком, и она там заведётся.

`.env` в git не попадает (правило `.env*` в `../.gitignore`), в образ Docker —
тоже (`.dockerignore`). Имена переменных со значениями по умолчанию — в `.env.example`.

**`.env` не едет деплоем.** Деплой возит код, секреты — нет. На сервере файл
создаётся отдельно (см. шаг «Настройки пульта» в `.github/workflows/deploy.yml`)
и при следующих деплоях не перезаписывается — иначе стирались бы пути к источникам,
которые есть только на сервере.

Если файл не доехал, пульт скажет об этом прямо на экране входа, а не будет
молча не пускать по правильному паролю.

## Как добавить счётчик

1. Создай файл в `counters/`, например `bookings-week.ts`.
2. Экспортируй объект типа `Counter` (см. `counters/types.ts`): `id`, `title`
   и `collect(env)`, который возвращает `{ value, caption? }`.
3. Допиши его в массив `COUNTERS` в `counters/registry.ts`.

Всё. Ни соседние счётчики, ни `page.tsx`, ни код приложения не меняются.

Счётчик может спокойно падать: `collectCounters` ловит исключение, эта плитка
показывает «нет данных», остальные считаются как обычно.

Данные собираются на каждый запрос — никакого кэша. Нажал F5 — увидел свежее.

## Как добавить источник в «Проверку связи»

1. Создай файл в `health/`, например `crm.ts`.
2. Экспортируй объект типа `HealthSource` (см. `health/types.ts`): `id`, `title`
   и `check(env)`, который возвращает `{ state, detail }`.
3. Допиши его в массив `SOURCES` в `health/registry.ts`.

`state` бывает `ok` (зелёная строка), `missing` (не подключено — это НЕ ошибка)
и `broken` (настроено, но не читается). В `detail` пиши, чего именно не хватает
и как это назвать: имя переменной, путь к файлу. Не «ошибка» и не стектрейс —
это читает владелец пульта.

Зелёным источник становится, только когда пульт реально до него достучался.

## Как унести пульт в другой проект

1. Скопируй папку `dashboard/` в корень другого Next.js-проекта.
2. Создай там `src/app/dashboard/page.tsx`:

```tsx
import DashboardPage from "../../../dashboard/page";

export const dynamic = "force-dynamic";
export default DashboardPage;
```

3. Скопируй `.env.example` в `.env` и впиши пароль.

`force-dynamic` объявляется именно в файле маршрута: настройки маршрута Next
читает оттуда, и переэкспорт может не заметить — страница начнёт кэшироваться
и показывать вчерашние цифры.

## Файлы

| Файл | Зачем |
| --- | --- |
| `config.ts` | чтение своего `.env`, пути, адрес подключения |
| `auth.ts` | проверка пароля и куки |
| `actions.ts` | серверные действия входа и выхода |
| `page.tsx` | вся страница |
| `health/` | источники для «Проверки связи», по файлу на источник |
| `counters/` | счётчики, по файлу на счётчик |
| `deploy/` | конфиг nginx, которым пульт выставляется наружу |

## Про безопасность

Вход — один общий пароль из `.env`, без учётных записей и без ограничения
попыток. Это учебный шлагбаум, как и пароль админки: он закрывает пульт
от случайного прохожего, но не от того, кто задался целью.

В куке лежит не пароль, а его отпечаток (SHA-256) — украденная кука пускает
внутрь, но сам пароль по ней не восстановить.

Пока пароль равен `admin`, пульт пишет об этом на странице. Появятся здесь
имена и телефоны клиентов — меняй пароль и возвращайся к вопросу авторизации.
